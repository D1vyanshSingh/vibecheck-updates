vulnscan 0.1.0 · field card

Engagement commands

python3 -m vulnscan from the repo root
authorised targets only

The scan

python3 -m vulnscan 10.0.0.5              # everything, automatic
python3 -m vulnscan 10.0.0.5 --no-pdf     # skip slow PDF render
python3 -m vulnscan 10.0.0.0/29 -q        # range, quiet

Defaults: 60 common ports · engine auto · HTML+JSON to out/ · PDF to Downloads · exit 1 if findings.

Client deliverable

python3 -m vulnscan 10.0.0.5 \
  -p 22,80,443,3306,6379 --strict \
  --reference "SOW-2026-014" --csv \
  -r "ACME Q1 external"

--strict = proved findings only; the suppressed count is still printed in the coverage section. --csv = asset inventory (host, port, service, version, CPE).

Ports

-p top60 common ports (default)
-p all1–65535, minutes per host
-p 8000-8100inclusive range
-p 22,80,8000-8100lists and ranges mix

Targets

python3 -m vulnscan a.example.com
python3 -m vulnscan 10.0.0.5,10.0.0.6
python3 -m vulnscan 10.0.0.0/29        # max 1024 hosts

Hostnames, IPv4, single IPv6, IPv4 CIDR. Refuses ranges over 1024 addresses.

Engines

--engine auto      # nmap if installed, else native
--engine native    # stdlib only, no nmap
--engine nmap      # require nmap, fail if absent

Native classifies the first bytes on the wire, one connection per port. nmap delegates to -sV plus scripts.

nmap evidence

--nse safedefault · safe-tagged scripts only
--nse extended+ ssl-enum-ciphers, ssh-auth-methods, http-enum
--nse offidentification only
--version-intensity 72–9, higher finds more

Vuln, exploit, DoS and brute script categories are never run, under any profile.

Reading confidence

certainprotocol-level proof on the wire; safe to quote to a client
firmstrong signal, not directly proved; verify before you report it
tentativeversion or path hint only, or a distro build that may be backported

Every finding carries the evidence that produced it — the request sent and the response received — plus its CVSS vector when one is known.

When a scan looks wrong

  • Fell back to native — nmap not on PATH; coverage section says so.
  • No PDF — needs Edge or Chrome; use --no-pdf and print the HTML.
  • Slow — avoid -p all; try -t 1.0 and fewer ports.
  • All timeouts — filtered host; raise -t, lower -c.
  • Odd CVE — read the backport note; --update-db for current ranges.

CVE database (offline)

python3 -m vulnscan --update-db                   # last 6 years, NVD
python3 -m vulnscan --update-db --db-years 2021,2024
python3 -m vulnscan host --db ./advisories.sqlite3
VULNSCAN_DB=/path/db.sqlite3 python3 -m vulnscan host

Only --update-db uses the network. Cache at ~/.cache/vulnscan. Range matching; distro builds downgraded to tentative for backports.

Saved defaults

--set-output-dir ./reports --set-pdf-dir ./reports
--show-config     --reset-config

Lab / proof checks

python3 -m vulnscan 127.0.0.1 -p 21,22,23,25,6379
python3 -m vulnscan --lab-exploits   # no target argument

Loopback-only, non-destructive, fixed proofs. Passing a target exits 2.

Recipes

# CI gate
python3 -m vulnscan 10.0.0.5 -q --no-pdf \
  || echo "findings present"

# no nmap, fast LAN
python3 -m vulnscan 10.0.0.5 \
  -p 1-1024 --engine native -t 1.5

# deep single-host pass
python3 -m vulnscan app.example.com \
  -p all --engine nmap --nse extended \
  --version-intensity 7 -c 128 \
  --reference "SOW-2026-014"

Triage order

  • Unauthenticated data stores — 6379 Redis, 27017 Mongo, 9200 Elasticsearch.
  • Control planes — 2375/2376 Docker, 10250 kubelet, 2379 etcd.
  • Remote access — 3389 RDP, 5900 VNC, 22 SSH auth methods.
  • Exposure hygiene — legacy TLS, expired certificates, version EOL.

Before it goes to the client

  • --strict run is the deliverable; the loose run stays in your notes.
  • --reference matches the SOW; scope section names the same targets.
  • Coverage section read: what was scanned, what was suppressed, was the CVE DB present.
  • Inventory CSV attached for their asset register.

What lands in the report

  • Scope, engine provenance, exact command line, any fallback reason.
  • Per-service identity: product, version, CPE, and whether it came from a banner, a handshake or a port guess.
  • Findings with severity, confidence, evidence, CVSS vector, plus per-host rollup.
  • Coverage: ports scanned, suppressed counts, advisory DB present.
  • Raw nmap XML beside the report (*.nmap.xml) when nmap ran.
